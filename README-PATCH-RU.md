# SnowfallMac v0.4 — Fluffy + Metal

Патч под текущую структуру `mighty097/mac`. Новые Swift-файлы и новые записи в `project.pbxproj` не нужны: обновляются существующие исходники и CI workflow.

## Установка

Распаковать содержимое архива в корень репозитория `mighty097/mac` с заменой файлов. Должны обновиться:

- `SnowfallMac/Sources/SnowOverlayView.swift`
- `SnowfallMac/Sources/AppDelegate.swift`
- `SnowfallMac/Sources/WindowGeometryProvider.swift`
- `SnowfallMac/Info.plist`
- `.github/workflows/build-macos.yml`

Затем сделать commit в `main`. GitHub Actions выполнит сборку и отдельно скомпилирует встроенный Metal shader через `xcrun metal`.

## Реализовано в этой версии

### Снег и глубина
- Два отдельных прозрачных окна на каждый дисплей: дальний снег позади обычных окон и передний слой поверх окон.
- MetalKit/MTKView для частиц. Снежинки идут одним instanced draw call; GPU shader рисует мягкое радиальное ядро с асимметричными пушистыми лопастями.
- Встроенный Metal shader компилируется во время запуска приложения. Если устройство или Metal pipeline недоступны, включается CoreGraphics fallback.
- Три диапазона глубины, разный размер и темп падения (скорость зависит от режима интенсивности), псевдо-3D поворот хлопьев и низкочастотное curl-поле ветра.
- Снижение непрозрачности крупных хлопьев рядом с курсором.

### Сугробы и окна
- Два слоя снежной массы: рыхлый свежий снег и постепенно уплотняемый нижний слой.
- Перераспределение снежной массы между соседними ячейками, ограничение угла откоса.
- Квадратичные кривые, округлённые окончания, небольшой свес на рамку, тень контакта, светлая и тёмная палитры, редкие искры.
- Отслеживание видимых окон через Core Graphics с сохранением порядка спереди назад.
- Скрытые части сугробов маскируются окнами сверху, но запас снега под ними не удаляется.
- Снег оседает на верхних кромках окон, на верхней кромке Dock (когда Dock расположен снизу) и у нижнего края дисплея.
- При перемещении или закрытии окна снег осыпается с прежнего места.
- Сметённые частицы могут осесть на другой видимой поверхности — каскадное пересыпание.

### Взаимодействие и режимы
- Курсор смахивает снег по всему отрезку между кадрами, а не только в конечной точке.
- Осыпание образует мягкий пылевой шлейф с инерцией, сопротивлением воздуха и вихревым движением.
- Курсор создаёт слабый воздушный поток вокруг падающих хлопьев.
- Haptic feedback с троттлингом при заметном объёме сметённого снега; поддержка зависит от Mac/трекпада.
- В меню: включение/выключение, «Очистить сугробы», «Только Finder», три интенсивности.
- Очистка сугробов плавная, не мгновенная.
- На батарее — 30 FPS и примерно на 40% меньше фоновых частиц; при питании от сети используется частота дисплея, с ограничением до 120 FPS.
- Перед полноэкранным окном передний слой очищается и приостанавливается.
- Таймеры и окна останавливаются при выключении дисплеев и запускаются после пробуждения.

## Важно знать

- Metal shader — встроенная строка Swift. В CI она извлекается и компилируется отдельной командой `xcrun metal`; это проверяет сам MSL-код до упаковки приложения.
- Type-check, линковка AppKit/MetalKit и работа приложения проверяются только настоящей macOS-сборкой GitHub Actions; Linux-проверка здесь ограничена синтаксическим разбором Swift.
- Восприятие сугробов на разных приложениях, Space и нескольких мониторах всё равно нужно проверить на реальном Mac. Список окон macOS не раскрывает абсолютно все приватные системные поверхности.
- Определение полноэкранного окна пока эвристическое по геометрии окна.
- На батарее режим 30 FPS/уменьшение числа частиц применяется при старте и проверяется повторно каждые 20 секунд.
- GitHub Actions продолжает собирать unsigned/ad-hoc app. Для распространения без Gatekeeper-предупреждения отдельно понадобятся Developer ID и notarization.

## Удаление дубля workflow

В репозитории ранее обнаружен корневой `build-macos.yml`, полностью дублирующий `.github/workflows/build-macos.yml`. GitHub запускает workflow-файлы только из `.github/workflows`; после установки патча удали корневой `build-macos.yml`, чтобы не путать его с активным workflow.
